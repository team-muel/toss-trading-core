# AMA-10 — Portfolio Accounting과 성과 기여도

Portfolio Accounting은 계좌 원장의 검증된 기간 시작 NAV, 종료 현금, 포지션 mark,
처분 lot, 외부 입출금, 배당·이자·수수료·세금을 하나의 보고 통화로 대사한다.
원통화 금액과 명시적 보고통화 FX를 항상 함께 받으며 통화를 암묵적으로 합산하지 않는다.

기존 `account_period`는 v1 호환 경로로 `보고통화 현금 + Σ(수량 × 시장가격 × 현재 FX)`를
사용한다. 이 계약은 기존 직렬화와 해시 재생을 위해 유지한다. 신규 v2 경로는
`account_period_with_nav`이며 아래의 포함관계 대사를 거친 NAV를 사용한다. 기간 총손익은
`종료 NAV - 시작 NAV - 순외부현금흐름`이다. 기여도는 local realized P&L,
local unrealized P&L, 배당, 이자, 수수료, 세금, FX로 분리하며 합이 총손익과
정확히 같지 않으면 `PORTFOLIO_ACCOUNTING_CONTRIBUTION_MISMATCH`로 차단한다.
수수료와 세금은 음수 비용만 허용한다.

TWR은 외부 현금흐름 직전 valuation으로 잘린 subperiod를 기하 연결한다. 다음
subperiod 시작 NAV는 직전 종료 NAV와 직후 입출금의 합과 정확히 일치해야 한다.
첫 시작 NAV, 마지막 종료 NAV, subperiod 현금흐름 합계도 각각 회계 기간의 시작 NAV,
종료 NAV, 외부 현금흐름 원장과 정확히 일치해야 한다.
따라서 입금 자체는 수익이 되지 않는다. 중간 valuation이 없는 현금흐름은 추정하지
않고 차단한다. MWR은 보조 XIRR 함수로 제공하며 투자자 관점에서 납입은 음수,
인출과 최종 NAV는 양수다. 해가 지정 bracket에 없으면 값을 만들지 않는다.

벤치마크 비교의 기초 인터페이스는 기하 상대수익
`(1 + portfolio_return) / (1 + benchmark_return) - 1`을 반환한다.
최종 결과의 canonical 필드를 SHA-256으로 묶고 JSON Schema를 wheel에 포함한다.
이 기능은 회계 계산만 수행하며 주문 또는 실거래 기능을 생성하지 않는다.

## AMA-101 — 포함관계 기반 기간 회계 v2

`AccountingNavSnapshot`은 계좌·원천 snapshot ID·기준 시각·provider 계약 버전과
NAV 구성요소, 브로커 보고 NAV, 계산 버전을 함께 받는다. 기초와 기말 모두
`reconcile_accounting_nav`로 대사한다. 현금·증권·결제 미수/미지급·기타 순자산은
포함관계에 따라 한 번만 계산하며 buying power는 자산에서 제외한다. 서로 다른 계좌·
보고통화, 역전된 시각, 재사용된 snapshot ID, 누락된 원천 식별자는 차단한다.

기말 증권 구성은 포지션 mark와 원통화·보고통화·FX별로 대사한다. 환산 합계가 우연히
같아도 통화나 FX가 다르면 거부한다. 증권 소계와 그 증권 하위 내역을 동시에 제공해
중복되는 경우에도 임의로 해석하지 않는다. 손익 기여도와 flow-boundary TWR은 v1과
같은 계산 함수를 사용하며, NAV 차이를 맞추기 위한 가상 현금이나 수익을 만들지 않는다.

예를 들어 현금 100 + 미수금 20이 결제 후 현금 120이 되면 NAV와 손익은 변하지 않는다.
원가 100인 증권을 110에 매도하면 미수금 발생 시 실현손익 10을 인식하고, 이후 현금으로
바뀌는 결제 과정에서는 추가 손익을 인식하지 않는다. 설명되지 않은 기타 자산 증가는
기여도 불일치로 차단되며, 결제 원금을 외부 입출금이나 수익으로 자동 분류하지 않는다.

`portfolio-accounting@2`는 기초·기말 NAV 증거와 기존 회계 결과를 함께 저장하고
전체를 새 해시로 묶는다. 원천 snapshot/계약 버전이 바뀌면 결과 금액이 같아도 v2 해시는
바뀐다. 기존 v1 결과 스키마와 해시는 수정하지 않는다.

이 API의 원천 ID와 포함관계는 호출자가 제공하는 검증 증거다. 실제 provider 응답의
계약 검증, snapshot 내용/시각의 진위·신선도 확인과 운영 원장 연결은 아직 별도 작업이다.
현재 golden tests는 fixture이며 Gate D2/E 또는 실제 계좌 통과 증거로 사용할 수 없다.
기존 mark/lot 기여도 계약도 그대로 유지하므로 여러 기간의 증분 mark 및 현금 FX 손익처럼
현재 입력으로 설명되지 않는 손익을 임의의 잔차로 보충하지 않는다.
